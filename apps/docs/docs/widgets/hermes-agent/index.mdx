### Summary metrics

| Metric        | Description                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------- |
| **Version**   | Hermes Agent application version reported by the API server or dashboard.                   |
| **Update**    | Commits behind the Hermes upstream branch, with published-release comparison as a fallback. |
| **Jobs**      | Active scheduled jobs compared with all reported jobs; failed jobs use an error state.      |
| **Skills**    | Enabled skills compared with all discovered skills.                                         |
| **Platforms** | Connected messaging platforms compared with all configured platforms.                       |
| **Toolsets**  | Enabled toolsets compared with all discovered toolsets.                                     |
| **Agents**    | Agents currently active in the gateway.                                                     |
| **Sessions**  | Active or recently returned sessions, depending on the selected Hermes surface.             |

### Responsive layout

![Hermes Agent widget adapting through its compact, strip, tall, standard, and showcase layouts](./img/responsive-layouts.webp "Hermes Agent responsive widget layouts")

The resize sequence covers every width and height combination from W1×H1 through W6×H4.

- The one-row 1×1 and 2×1 tiles use dedicated compact layouts that fill the available height and make each visible metric a full-tile link. They prioritize readable text labels over decorative metric icons, while the 2×1 tile also uses a compact gateway state to preserve the integration name.
- Every H1 layout uses a single-line identity header. The W3×H1 strip balances six labeled metrics in a 3×2 grid; wider W4×H1 through W6×H1 strips place the same metrics in one row, show full version and skill values, and make every metric tile a direct Hermes dashboard link. Compact strips omit decorative metric icons so long labels retain the available width. Their type also scales with the physical row height, preventing tiny labels on large boards. W5×H1 and wider strips surface failed-job detail when present.
- W1×H2 through W1×H4 tiles keep a single metric-grid column, including when a large board makes W1 wider in pixels. They show all eight summary metrics with visible labels and distribute them across the full height. Short physical rows use an icon-free label-and-value line; as height becomes available, each tile progressively enlarges and stacks its label with its value.
- Typography scales continuously with both available width and height: titles, status badges, metric labels, values, detail rows, and footer text grow when the widget has room. Detail lists use the width of their individual panel, so narrow W3/W6 columns stay compact while wider panels remain easy to scan.
- Medium tiles add platforms, toolsets, agents, and sessions.
- Detail panels are selected from the available height, and each list is capped to the number of rows that fits. The widget does not introduce an inner scrollbar; larger tiles progressively reveal more sessions, jobs, platforms, and toolsets.
- Scheduled-job names use one line when the panel is wide and up to three lines in narrow multi-column panels. Multi-line panels reduce their row count to preserve the no-scroll layout.
- Large tiles show optional platform, recent-session, scheduled-job, and toolset sections. Each section can be disabled in the widget configuration.
- The detailed card follows the canonical Nous Research Hermes Teal direction: a deep teal canvas, warm cream text, emerald and amber state accents, technical monospace values, and uppercase brand chrome. Disable the brand theme option to follow the current Homarr theme in light and dark mode instead.
- Recent sessions use single-line titles with compact source icons for Telegram, cron, web, API, CLI, and other adapters. Full titles remain available on hover. Message previews, chat and user identifiers, and token or cost metrics are discarded at the server-side integration boundary.
- Dashboard mode makes the title, dashboard badge, summary metrics, and visible detail panels link to their matching Hermes dashboard page when an external integration URL is configured. The internal server-to-server URL is never sent to the browser.
- Scheduled jobs dedicate the full row width to the job name. Failed jobs sort first, followed by paused and enabled jobs. Failed, paused, and enabled names use error, warning, and success colors instead of repeating a status word; when a job is both failed and paused, the paused warning state takes visual precedence. The full name, textual state, and schedule remain available to assistive technology and on hover. Raw prompts, scripts, and error messages are never exposed because they can contain sensitive values.
- Platform rows use a compact state dot and clock icon so long platform names keep priority. Hovering the indicators reveals the textual state and last update time.

### Privacy and public boards

The widget always returns a narrow, server-generated data model instead of forwarding Hermes API objects to the browser. Anonymous visitors and board viewers without direct permission to use the Hermes integration receive aggregate health and count metrics only. Session titles, job names and schedules, platform names, and toolset names require direct `use` permission for that integration.

Widget display options only control presentation. They are not used as access controls; sensitive fields are removed or withheld by the server before the response is sent.

### Data modes and refresh

API server mode on port `8642` requires the configured bearer API key. The current API returns recent session metadata but does not expose messaging chat, channel, or topic identifiers, so the widget reports configured platform status without claiming channel-level data.

Dashboard mode on port `9119` uses the public status endpoint and, when a local or otherwise unprotected dashboard exposes its short-lived session token, also loads the exact Hermes updater status, sessions, jobs, skills, and toolsets. Homarr does not perform an interactive dashboard login; protected detail endpoints are labeled as unavailable.

Data is cached for 30 seconds and refreshed in the background. The dashboard updater result follows Hermes' own cache policy. GitHub release fallback checks are cached for one hour and are skipped when external connections are disabled.

The API contract was verified against Hermes Agent `v0.20.0` (`v2026.8.3`). Later Hermes versions may add fields, but Homarr only parses and returns the documented safe subset.
